🔍 What We Covered:

✅ What is Sorting? – Arranging data in a logical order (ascending/descending) to make searching, processing, and analysis more efficient.

✅ In-Place vs. Out-of-Place Sorting:
• In-Place Sorting – Sorts the list without using extra space (e.g., Bubble Sort, Selection Sort).
• Out-of-Place Sorting – Requires extra memory to store a new sorted version (e.g., Merge Sort).

✅ Stable vs. Unstable Sorting:
• Stable Sorting – Maintains the original order of equal elements (e.g., Bubble Sort).
• Unstable Sorting – Does not guarantee original order preservation (e.g., Selection Sort).

✅ Bubble Sort – Repeatedly swaps adjacent elements until the list is sorted.
✅ Selection Sort – Finds the smallest element and places it in its correct position, one at a time.

🚀 Day 16: Lecture on Sorting Part I (Continued)

Today, we continued our Sorting lecture by covering two more important sorting algorithms: Insertion Sort and Counting Sort.

🔍 What We Covered:

✅ Insertion Sort – Builds a sorted list one element at a time, shifting elements as needed.

✅ Counting Sort – A distribution-based sorting algorithm that works well when the range of numbers is small compared to the number of elements. Faster than comparison-based sorting but requires extra space.

✅ Time Complexity Comparison:

Algorithm Best Case | Average Case | Worst Case
🔹Bubble Sort O(n) O(n²) O(n²)
🔹Selection Sort O(n²) O(n²) O(n²)
🔹Insertion Sort O(n) O(n²) O(n²)
🔹Counting Sort O(n+k) O(n+k) O(n+k)

🚀 Which Sort to Use?

• Use Insertion Sort when the array is small or nearly sorted.
• Use Counting Sort when dealing with a small range of values (non-comparative sorting).
• Bubble Sort and Selection Sort are generally not the best choices unless for learning purposes or very small inputs.

🚀 Day 17: Lecture on Two Pointers Technique

Today, we explored the Two Pointers technique—one of the most powerful and commonly used techniques for optimizing solutions to array and string problems. Instead of using nested loops (O(n²)), Two Pointers helps us solve problems efficiently in O(n)! 🔥

🔍 What We Covered:

✅ Definition – Using two different pointers to track array indices for solving problems efficiently.

✅ Different Variants & Their Problem Patterns:
🔹 Variant I: Parallel Pointers – Used for problems that require comparing adjacent elements (e.g., checking if an array is sorted).
🔹 Variant II: Pointers on Separate Arrays – Used for merging two sorted arrays efficiently.
🔹 Variant III: Colliding Pointers – Solving problems like two sum in a sorted array by moving two pointers toward each other.
🔹 Variant IV: Seeker and Placeholder – Used for modifying arrays in-place, like moving non-zero elements to the front.
🔹 Variant V: For-While Combo – When one pointer moves one step at a time, but the other moves multiple steps (e.g., counting smaller elements in two sorted arrays).

🚀 Day 34: Topological Sort

Last weeks lecture was all about Topological Sorting—a key algorithm used when solving problems involving dependencies, especially in Directed Acyclic Graphs (DAGs).

📚 What We Covered:

✅ Introduction & Motivation
• Topological sort arranges tasks so each task appears before those that depend on it.
• Only possible on DAGs (Directed Acyclic Graphs)—no cycles allowed!
✅ Two Main Implementations:
1. BFS (Kahn’s Algorithm)
• Starts with nodes having no incoming edges.
• Removes nodes level by level while tracking dependencies.
• Efficient and intuitive.
2. DFS-Based Approach
• Recursively explores paths and builds the order in reverse.
• Uses a color system (White, Gray, Black) to track cycles.
• Great for sparse graphs.
✅ Time & Space Complexity:
• Both BFS and DFS take O(V + E), where V = vertices and E = edges.
✅ Real-Life Applications:
• Course scheduling 🏫
• Task automation 🛠
• Dependency resolution (e.g., compilers, package managers)
• Detecting deadlocks 🧠
• Git commit history & Airflow workflows 🌐
✅ Common Pitfalls:
• Forgetting to check all components in the graph
• Cycle detection mistakes using vanilla BFS/DFS
• Incorrect assumption of node ordering when dependencies exist

🚀 Day 35: Dynamic Programming🔁

Yesterday we officially entered the land of Dynamic Programming—the technique every problem solver fears at first... until they fall in love with its elegance! ❤️‍🔥

🧠 What We Covered:

✅ Intro to DP:
Dynamic Programming (DP) solves complex problems by breaking them into simpler overlapping subproblems and storing their results to avoid redundant work.
Top-down DP = Recursion + Memoization.
✅ Memoization:
Storing results of expensive recursive calls in a data structure (like a dictionary) so we don’t recompute them again. Huge time-saver!
✅ Two Essential Conditions:
1. Optimal Substructure – An optimal solution depends on optimal solutions of its subproblems.
2. Overlapping Subproblems – The problem can be broken into smaller, repeated subproblems.
✅ Common DP Applications:
• Enumeration (e.g. Climbing stairs)
• Optimizations (e.g. House Robber)
• Yes/No decisions (e.g. Partition Equal Subset Sum)
✅ Important Reminders:
• Always define the state of your subproblem.
• Have a base case to stop recursion.
• Watch out for missing parameters when memoizing.

🚀 Day 36: DP II – Bottom-Up Approach

Yesterday, we explored the bottom-up (tabulation) approach to dynamic programming. Unlike top-down, which starts with the big picture and breaks things down, bottom-up builds solutions from smaller subproblems up to the full solution.

🧠 What We Covered:

✅ What is Bottom-Up DP?
• A technique that solves smaller subproblems first and combines them to solve larger ones. It avoids recursion and improves time efficiency.
✅ Why use it?
• No recursion overhead
• Better memory optimization
• Sometimes easier to debug and iterate
✅ Top-down to Bottom-up Conversion Recipe
1. Represent your state-space
2. Initialize base cases
3.Define state transitions
4. Respect the dependency order
5.Return the answer for the initial state
✅ Common Variants
• Counting (e.g., number of ways)
• Optimization (min/max problems)
• Decision (yes/no answers)
✅ Common Pitfalls
• Assuming it’s always faster than top-down
• Incorrect initialization
• Overlooking edge cases

🚀 Day 41: Tries (Prefix Trees)

Yesterday, we explored Tries — a powerful tree-based data structure for efficient string storage and retrieval. 🌳🔡

🧠 What We Covered

✅ What are Tries?
• A tree structure used to store strings where each node represents a character.
• Also called prefix tree or digital tree.
✅ Why Trie?
• Fast prefix and word lookups (like in dictionaries, autocomplete, or spell checkers).
• Saves space when many words share prefixes.
✅ Operations on Tries
• Insertion → add words character by character, marking the end node.
• Search Prefix → check if a given prefix exists by traversing nodes.
• Search Word → same as prefix search, but also check is_end flag.
• Deletion → carefully remove nodes depending on whether the word is unique, prefix of another, or has prefixes itself.
✅ Time & Space Complexity
• Insertion: O(n)
• Search: O(n)
• Deletion: O(n)
(where n = length of word)
• Space: O(M × N) in worst case (M = number of words, N = length of longest word), but often less in practice thanks to shared prefixes.

🚀 Day 42: Shortest Path Algorithms

In this session, we explored the core algorithms that power navigation systems, graph optimization, and route planning! 🗺✨

🧠 What We Covered

✅ Dijkstra’s Algorithm
• Finds the shortest path from a single source to all other nodes in a weighted graph (no negative edges).
• Uses a min-heap to pick the closest unvisited node.
• Time Complexity: O((V + E) * logV)
• Space Complexity: O(V)
✅ Bellman–Ford Algorithm
• Works even with negative weights.
• Repeatedly relaxes all edges up to V−1 times.
• Detects negative weight cycles if a distance decreases after the Vth iteration.
• Time Complexity: O(V * E)
• Space Complexity: O(V)
✅ Shortest Path Faster Algorithm (SPFA)
• An optimization of Bellman–Ford using a queue.
• Only processes vertices whose distances were updated.
• Can detect negative cycles using edge count tracking.
• Average Time: O(E), Worst Case: O(V * E)
• Space Complexity: O(V)
✅ Floyd–Warshall Algorithm
• Computes shortest paths between all pairs of nodes.
• Dynamic programming approach using intermediate nodes.
• Time Complexity: O(V³)
• Space Complexity: O(V²)

🚀 Day 43: Advanced String Algorithms

we wrapped up the DSA journey with the fascinating world of substring search algorithms, learning how to find patterns efficiently within strings — the foundation of search engines, DNA analysis, and text editors! 🧬✨

🧠 What We Covered

✅ What is a Substring Search? (Naive Method)
• The simplest approach — slide the pattern over the text one by one and compare.
• Time Complexity: O(n × m), where n = length of text and m = length of pattern.
✅ Rabin–Karp Algorithm (Rolling Hash)
• Uses hashing to compare substrings efficiently.
• Converts strings to numerical values using polynomial rolling hash.
• Average Time Complexity: O(n + m)
• Handles substring comparisons with modular arithmetic and base powers.
✅ Knuth–Morris–Pratt (KMP) Algorithm
• Guarantees O(n + m) time complexity.
• Avoids re-checking characters by building an LPS (Longest Prefix Suffix) array.
• Two stages:
- Preprocessing: Build the LPS table in O(m).
- Matching: Use LPS to skip unnecessary comparisons in O(n).
✅ Additional String Algorithms
• Z Algorithm: Finds all occurrences of a substring; efficient for multiple pattern matches.
• Manacher’s Algorithm: Finds the longest palindromic substring in O(n).
• Suffix Array: Solves problems related to lexicographic order, substring search, and LCP (Longest Common Prefix).
